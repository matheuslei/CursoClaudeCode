# Roteiro de narração · Módulo 4 (aulas 4.2 a 4.5)

Texto adaptado para a fala. A legenda de cada cena fica no `fala` da aula.

## Aula 4.2: Auto mode

| Arquivo | Texto para narrar |
|---|---|
| `m4a2-01.mp3` | Aprovar dezenas de pedidos por tarefa cansa. E quem cansa aprova sem ler. O auto mode resolve isso. |
| `m4a2-02.mp3` | No auto mode, um modelo classificador separado revisa cada ação antes de ela rodar. O que parece seguro roda direto. O que parece arriscado é bloqueado. |
| `m4a2-03.mp3` | Por padrão, ele bloqueia coisas como baixar e executar código, force push, deploys de produção e git reset hard. |
| `m4a2-04.mp3` | E libera o dia a dia: operações de arquivo na pasta de trabalho, instalar dependências a partir dos manifestos e push para as branches do repositório, exceto as de deploy. |
| `m4a2-05.mp3` | Depois de três bloqueios seguidos ou vinte no total, ele volta a perguntar para você. E um combinado na conversa, como não faça push, não vira regra. |
| `m4a2-06.mp3` | Lembre: o auto mode reduz pedidos, mas não garante segurança. Para proibir de verdade, use uma regra deny. |

## Aula 4.3: Regras allow, ask e deny

| Arquivo | Texto para narrar |
|---|---|
| `m4a3-01.mp3` | Os modos são o volume geral. As regras são o ajuste fino das permissões. |
| `m4a3-02.mp3` | Allow libera sem perguntar, como rodar os testes. Ask sempre pergunta, como um push. Deny bloqueia, como ler o arquivo ponto env. |
| `m4a3-03.mp3` | A ordem de avaliação é deny, depois ask, depois allow. Se houver conflito, o bloqueio vence, inclusive entre arquivos diferentes. |
| `m4a3-04.mp3` | O formato é o nome da ferramenta e, entre parênteses, o especificador. Coloque o asterisco depois do subcomando, para não liberar mais do que queria. |
| `m4a3-05.mp3` | As regras moram em arquivos de settings: o do usuário vale para todos os seus projetos, o do projeto é compartilhado com o time, e o local é só seu. |
| `m4a3-06.mp3` | Escrever no Claude ponto MD influencia o Claude, mas não impede. Para impedir de verdade, use deny. E confira tudo com barra permissions. |

## Aula 4.4: Sandbox

| Arquivo | Texto para narrar |
|---|---|
| `m4a4-01.mp3` | Regras olham o texto do comando. Mas um comando pode fazer mais do que o texto revela. |
| `m4a4-02.mp3` | Um script Python pode apagar arquivos, e um npm install acessa a internet. O sandbox impede isso no nível do sistema operacional, mesmo que o comando tente. |
| `m4a4-03.mp3` | Ele isola a escrita, que só vale na pasta de trabalho, e a rede, que só alcança domínios autorizados. A lista começa vazia. Mas atenção: por padrão, a leitura continua ampla. |
| `m4a4-04.mp3` | Funciona no macOS, no Linux e no WSL dois. No Windows nativo e no WSL um, não funciona. No Windows, rode o Claude Code dentro do WSL dois. |
| `m4a4-05.mp3` | Ficam fora do sandbox as ferramentas de arquivo e web do Claude, os hooks, os servidores MCP locais e os comandos que você digita com exclamação. |
| `m4a4-06.mp3` | Regras controlam as ferramentas do Claude. O sandbox controla o que os comandos conseguem fazer. Juntos, formam uma defesa em camadas. |

## Aula 4.5: Segredos e dados pessoais

| Arquivo | Texto para narrar |
|---|---|
| `m4a5-01.mp3` | Tudo o que entra no contexto é enviado pela rede ao modelo. Inclusive aquele token colado só para testar. |
| `m4a5-02.mp3` | Um segredo pode vazar pelo prompt, por um arquivo que o Claude leu, ou pela saída de um comando. |
| `m4a5-03.mp3` | Guarde segredos no ponto env, fora do Git. Crie um ponto env ponto example com valores falsos. E bloqueie a leitura com uma regra deny. |
| `m4a5-04.mp3` | Vazou? Revogue e gere outro. Apagar o arquivo depois não remove do histórico do Git. Se for credencial corporativa, avise a área responsável. |
| `m4a5-05.mp3` | Para estudar, use dados fictícios. Precisa de uma base real? Primeiro confirme com a área de privacidade. E prefira scripts que processam os dados localmente. |
| `m4a5-06.mp3` | Isto são boas práticas gerais, não orientação jurídica. Antes de usar dados reais, consulte a área de segurança da informação e a de privacidade da sua organização. |
| `m4a5-07.mp3` | A regra de ouro: o que não deve sair, não entra no contexto. |
