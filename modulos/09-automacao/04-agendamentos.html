Tarefas agendadas e loops

Objetivo: repetir um pedido com /loop, conhecer as tarefas agendadas do app Desktop e da nuvem, diferenciar /loop de /goal e escolher a ferramenta certa para cada rotina, de olho no custo.

▶ Vídeo da aula ~1 min

Comece por aqui: um resumo animado e narrado. Clique no vídeo ou aperte Espaço para pausar.

1Por que importa

Algumas tarefas não são "faça agora", e sim "faça de tempos em tempos": ver se o build terminou, rodar os testes a cada meia hora, revisar os commits do dia toda manhã. Em vez de lembrar de pedir, você agenda. O desafio é escolher onde a tarefa roda (na sessão aberta, no seu computador ou na nuvem) e não deixar um agendamento esquecido gastando o seu plano.

Aviso de custoTodo disparo de um agendamento é um novo turno: ele envia o contexto e consome o seu plano, mesmo com você longe do teclado. Prefira intervalos longos, pedidos curtos e cancele o que não precisa mais. O /usage mostra uma linha para os loops mais pesados (v2.1.242 ou mais nova).

PontoComo funciona
IntervaloUnidades s, m, h, d; o mínimo é 1 minuto (segundos são arredondados para cima). Intervalos "quebrados", como 7m, são ajustados e o Claude avisa qual escolheu.
Sem intervaloO Claude escolhe a espera a cada rodada, entre 1 minuto e 1 hora, e diz o motivo.
Sem pedidoRoda um prompt de manutenção embutido (continuar trabalho pendente, cuidar do PR da branch, limpezas) ou o seu .claude/loop.md.
Quando disparaSó com o Claude Code aberto e ocioso, entre os seus turnos. Fechou o terminal, parou. Horários têm uma pequena variação proposital.
DuraçãoTarefas recorrentes expiram em 7 dias. Até 50 tarefas por sessão.
PararLoop com ritmo do Claude: Esc com o campo vazio. Loop de intervalo fixo: peça "cancele o loop dos testes" (Esc e Ctrl+C não param).
ListarPergunte "quais tarefas agendadas eu tenho?". Cada uma tem um ID de 8 caracteres.

Para um lembrete único, não precisa de /loop: escreva em linguagem natural, como "daqui a 45 minutos, confira se os testes passaram". Para desligar o agendador da sessão: variável de ambiente CLAUDE_CODE_DISABLE_CRON=1.

/loop ou /goal?

O próximo turno começa quando…Para quando…
/looppassa um intervalo de tempovocê cancela, o Claude decide que acabou (ritmo próprio) ou vencem 7 dias
/goal (Módulo 7)o turno anterior terminaum modelo avaliador confirma a condição (ou a julga impossível), ou você usa /goal clear

Regra prática: esperar algo de fora (build, deploy, PR) → /loop. Trabalhar até um resultado (testes passando) → /goal. O /goal também roda no -p: claude -p "/goal ..." vai até o fim numa só chamada.

Quanto conferir o que rodou sozinho?

Loop, /goal, tarefa agendada e claude -p têm uma coisa em comum: o Claude trabalha sem você olhando. A regra é simples: quanto menos você acompanhou, mais você confere.

Como foi o trabalhoO que conferir antes de aceitar
Você acompanhou cada passoLeia o diff final e rode os testes uma vez.
/goal ou loop com você por pertoOs testes você mesmo; o diff inteiro; se nada fora do pedido mudou.
Agendado, -p ou noturno, sem ninguémTudo acima, mais: o que ele disse que fez bate com o que fez (histórico e git log)? Revisão com contexto novo (/code-review, aula 9.2) antes de juntar.

E dá para não depender da memória: um hook de Stop (Módulo 5) roda toda vez que o Claude vai encerrar o turno. Se o script sair com código 2, o Claude não para: o texto do erro volta para ele como motivo para continuar.

.claude/settings.json (trecho){ "hooks": { "Stop": [ { "hooks": [ { "type": "command", "command": "python \"${CLAUDE_PROJECT_DIR}/.claude/hooks/testes_antes_de_parar.py\"" } ] } ] } }

O script roda python -m unittest. Se falhar, sai com 2 e manda o fim do erro; se passar, sai com 0. Está em projeto-taskflow/etapa-09/gabarito/.claude/hooks/testes_antes_de_parar.py (testado em 19/11/2026: libera com testes passando, bloqueia com testes falhando).

Evite o laço sem fimO hook recebe stop_hook_active: true quando o Claude já está continuando por causa dele. O script do gabarito libera a parada nesse caso. Além disso, o Claude Code ignora o bloqueio depois de várias continuações seguidas sem uso de ferramenta. Um teste que nunca passa vira só uma mensagem de erro, não um gasto infinito, mas confira mesmo assim.

7Exercício real: um loop curto e cancelado

Use a pasta de treino do Módulo 9 (README da etapa 09).

CustoCada disparo consome o seu plano. Deixe o loop rodar uma ou duas vezes e cancele. Não saia deixando um loop ativo.
  1. Abra o claude na pasta de treino e rode: /loop 5m rode python -m unittest e responda só OK ou FALHOU. Leia a confirmação: intervalo e ID da tarefa.
  2. Pergunte: "quais tarefas agendadas eu tenho?". Ache o ID e o próximo horário.
  3. Depois de um ou dois disparos, peça: "cancele o loop dos testes". Pergunte de novo a lista para confirmar que ficou vazia.
  4. (Opcional) Crie .claude/loop.md com o seu pedido padrão (modelo em gabarito/.claude/loop.md), rode /loop sem nada, espere uma rodada e pare com Esc no campo vazio.
  5. Compare com o /goal: /goal python -m unittest mostra OK nesta conversa, ou pare após 3 turnos. Qual dos dois depende do relógio?
  6. (Opcional, Desktop) No app, aba Code › Scheduled › New task: crie uma tarefa local na pasta de treino com horário Manual e clique em Run now. Assim nada roda sozinho depois.
Ver o gabarito
  • Passo 1: o Claude converte 5m no cron */5 * * * *, agenda e confirma o ritmo e um ID de 8 caracteres. A cada disparo, roda os testes e responde OK (o TaskFlow tem 6 testes passando).
  • Passos 2 e 3: por baixo, o Claude usa as ferramentas CronList (listar) e CronDelete (cancelar pelo ID). Esc não cancela um loop de intervalo fixo; é preciso pedir.
  • Passo 4: conteúdo de exemplo do .claude/loop.md:
    .claude/loop.mdRode python -m unittest. Se todos os testes passarem, responda só "OK, N testes". Se algum falhar, mostre o nome do teste e a primeira linha do erro. Não edite arquivos.
    Sem intervalo, o Claude escolhe a espera; Esc com o campo vazio para esse tipo de loop.
  • Passo 5: o /loop depende do relógio; o /goal depende da condição. Com os testes já passando, o /goal deve terminar logo no primeiro turno.
  • Passo 6: com Manual, a tarefa só roda quando você clica em Run now. Se aparecer pedido de permissão, responda na sessão da execução (lista History da tarefa).

8Erros comuns

Loop esquecido

Um /loop 1m deixado aberto dispara 60 vezes por hora, cada vez com todo o contexto. Use intervalos longos e cancele.

Achar que Esc para tudo

Esc só para o loop de ritmo próprio. O de intervalo fixo se cancela pedindo ao Claude.

Esperar que rode com o terminal fechado

/loop vive na sessão. Para rodar sem ela, use Desktop (PC ligado) ou nuvem.

Usar /loop para "até passar"

Repetir no relógio até os testes passarem desperdiça disparos. Isso é trabalho para o /goal.

Nuvem com código da empresa

A tarefa na nuvem clona o repositório fora do seu PC. Só com aval da segurança da informação.
