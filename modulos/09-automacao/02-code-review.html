Revisão de código com o Claude

Objetivo: revisar mudanças antes de juntar com /code-review (alvo, esforço e --fix), checar segurança com /security-review e saber quando usar o seu subagente revisor.

▶ Vídeo da aula ~1 min

Comece por aqui: um resumo animado e narrado. Clique no vídeo ou aperte Espaço para pausar.

1Por que importa

Quem escreveu o código é a pior pessoa para revisá-lo: você lê o que quis escrever. Um revisor com outro olhar pega o índice errado, a docstring que mente, o eval esquecido. O Claude Code tem revisores prontos, que você chama com um comando e que também podem rodar em script (aula 1) e no GitHub (aula 3).

AnalogiaÉ o "passa o olho aqui antes de eu mandar?" que você pede a um colega. Só que disponível a qualquer hora, sempre com o mesmo método. E, como com o colega, a decisão final continua sendo sua.

2Conceito: como o /code-review trabalha

3Os revisores e como apontar cada um

/code-review (alias /review)

Procura bugs de funcionamento nas mudanças da sua branch. Funciona em qualquer plano e consome o uso como o resto da sessão. No terminal, roda como subagente em segundo plano, com contexto próprio (Módulo 7): você continua trabalhando e os achados chegam na conversa.

sintaxe/code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [alvo]
Para revisarDigite
A branch atual e o que ainda não tem commit/code-review
Os últimos 15 commits/code-review HEAD~15..HEAD
Uma branch contra outra/code-review main...minha-branch
Um pull request pelo número/code-review 1234
Um arquivo ou pasta/code-review buscar.py

Sem alvo, ele revisa os commits à frente da branch remota mais as mudanças sem commit. Se a branch não tem remota, compara com main ou com o commit anterior.

OpçãoO que faz
low … maxEsforço. low traz os achados de que tem mais certeza (menos alarme falso); níveis mais altos ampliam a cobertura e gastam mais. Sem nível, ele reusa o último que você digitou.
--fixDepois de revisar, aplica as correções. As edições passam pelo seu modo de permissão.
--max-findingsMuda quantos achados aparecem (v2.1.288 ou mais nova).
--commentPublica os achados num PR do GitHub ou MR do GitLab. Fora do escopo deste curso offline.
ultraRevisão profunda na nuvem (ultrareview), com vários agentes; exige conta claude.ai. Envia o código para fora do seu PC: em código da empresa, só com aval da segurança da informação.
--fix e o /rewindUma revisão em segundo plano aplica o --fix fora dos checkpoints da sessão: o /rewind não desfaz essas edições. Faça commit antes e, se não gostar, desfaça pelo Git.

O /code-review segue o seu CLAUDE.md, inclusive no -p. Em script, ele roda em primeiro plano e imprime os achados: claude -p "/code-review low" --max-turns 10.

/security-review

Olha só para segurança: injeção, problemas de autenticação, exposição de dados. Compara a sua branch com origin/HEAD, ou seja, precisa de um remoto origin. Sem ele, falha com ambiguous argument 'origin/HEAD...'. Para treinar sem internet, o "remoto" pode ser outra pasta do seu PC (veja o exercício).

Caráter informativoUma revisão automática de segurança ajuda a achar problemas, mas não é parecer de segurança. Em sistemas da empresa, decisões de segurança e privacidade (LGPD) passam pela área competente.

Qual revisor usar?

RevisorProcuraQuando
/code-reviewBugs de funcionamentoAntes de juntar qualquer mudança
/security-reviewVulnerabilidadesMudanças que tocam entrada de usuário, arquivos, autenticação, dados
revisor-taskflow (Módulo 7)Regras do seu projetoChecklist da equipe: docstrings, dados fictícios, idioma, testes
/simplifyLimpeza (reuso, simplicidade)O código funciona, mas pode ficar mais simples. Não procura bugs.

Quer outro comportamento? Uma skill de projeto chamada code-review substitui a embutida; o alias /review continua chamando a original.

7Exercício real: revisar um arquivo com problemas

Use a pasta de treino com Git (passos 1 e 2 do README da etapa 09).

Custo e dadosCada revisão consome o seu plano: use low no primeiro teste e não use ultra aqui. Só código de treino com dados fictícios.
  1. (Opcional, para o /security-review) Ainda na main, crie um remoto local:
    PowerShellgit init --bare ..\origem-taskflow.git git remote add origin ..\origem-taskflow.git git push -u origin main git remote set-head origin main
  2. Crie uma branch: git switch -c busca.
  3. Copie projeto-taskflow/etapa-09/gabarito/buscar_com_bug.py (do curso) para a pasta de treino com o nome buscar.py. Ele tem problemas de propósito. Depois: git add buscar.py e git commit -m "busca".
  4. Abra o claude e rode /code-review low. Continue conversando enquanto ele trabalha.
  5. Se criou o remoto no passo 1, rode /security-review. Compare os achados.
  6. Peça a correção (/code-review --fix ou à mão), crie tests/test_buscar.py e rode python -m unittest.

8Erros comuns

Aceitar tudo sem ler

Revisão automática erra para os dois lados: inventa problema e deixa passar outro. Leia cada achado antes de corrigir.

--fix sem commit antes

As edições da revisão em segundo plano não voltam com /rewind. Faça commit primeiro e desfaça pelo Git se precisar.

Usar ultra em tudo

ultra roda na nuvem, custa mais e envia o código para fora do PC. Comece com low.

/security-review sem origin

Ele compara com origin/HEAD. Sem remoto, falha antes de começar.

Confundir com /simplify

/simplify só limpa o código. Para achar bugs, use /code-review.
