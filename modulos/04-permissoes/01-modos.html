Modos de permissão

Objetivo: conhecer os seis modos de permissão, saber trocar entre eles e escolher o modo certo para cada situação.

▶ Vídeo da aula ~1 min

Comece por aqui: um resumo animado e narrado. Clique no vídeo ou aperte Espaço para pausar.

1Por que importa

O modo de permissão define o que o Claude pode fazer sem perguntar. Modo errado tem dois custos: perguntas demais (você aprova no automático e para de ler) ou perguntas de menos (algo é feito sem você ver). Escolher bem o modo é o equilíbrio entre velocidade e controle.

CenárioVocê vai só investigar um bug sem mexer em nada: use plan. Vai implementar algo que já planejou num projeto de estudo com Git: acceptEdits ou auto agilizam. Vai rodar num servidor de produção: nenhum modo "liberado".

2Conceito: do mais restrito ao mais liberado

3Os modos em detalhe

Modo (valor)Roda sem perguntarQuando usar
default (rótulo Manual)Só leituras. Toda edição, comando ou acesso à rede pergunta.Aprendendo; projeto sensível; quer ver cada passo
acceptEditsLeituras, edições de arquivo e comandos comuns de arquivo (mkdir, touch, mv, cp, rm, rmdir, sed) dentro da pasta de trabalho. Caminhos protegidos ainda perguntam.Implementar algo já combinado, com Git como rede
planLeituras (e comandos aprovados pelo classificador do auto mode, quando disponível). Edições ficam bloqueadas até você aprovar o plano.Investigar, planejar antes de mexer (Módulo 3)
autoTudo, com um classificador revisando cada ação em segundo planoMenos interrupções com uma camada de segurança (próxima aula)
dontAskSó o que já está pré-aprovado por regras. O que perguntaria é negado.CI e scripts (Módulo 9)
bypassPermissionsTudo, sem perguntas nem checagens de segurançaSó em ambientes isolados (container, VM, sem internet)
Regras deny valem em todos os modosMesmo no bypassPermissions, uma regra deny continua bloqueando. Já as regras allow não fazem diferença nesse modo, porque tudo é permitido. Veremos regras na aula 4.3.

Como trocar de modo

Durante a sessão: Shift+Tab (em alguns terminais Windows, Alt+M). Se você está em auto, o primeiro toque vai para default; depois o ciclo segue default → acceptEdits → plan (e outros modos, quando habilitados). A barra de status mostra o modo ativo.

Ao abrir:

claude --permission-mode plan claude --permission-mode acceptEdits claude --permission-mode default

Como padrão, no settings.json (Módulo 5 aprofunda):

{ "permissions": { "defaultMode": "default" } }
Modo inicial atualSegundo a documentação, a partir da versão 2.1.283 as sessões interativas no terminal e no VS Code começam em auto por padrão. Confira o modo na barra de status assim que abrir. Se preferir aprender aprovando cada passo, volte para default com Shift+Tab ou fixe o defaultMode.
--dangerously-skip-permissionsEquivale a bypassPermissions. A própria documentação recomenda usar só em containers, VMs ou dev containers sem internet, e avisa que não há proteção contra prompt injection. Numa máquina de trabalho, não use.

5Pratique: qual modo?

O terminal descreve situações. Responda com o nome do modo (default, acceptEdits, plan, auto, dontAsk ou bypassPermissions). Comece com iniciar.

6Quiz

7Exercício real

No TaskFlow (com tudo commitado):

  1. Abra com claude e anote qual modo aparece na barra de status
  2. Aperte Shift+Tab várias vezes e observe o ciclo de modos
  3. Em plan, peça: adicione o comando "editar <numero> <novo titulo>". Repare que ele investiga e propõe um plano, sem editar
  4. Aprove o plano e escolha seguir com edições aprovadas automaticamente (ou troque para acceptEdits)
  5. Revise com ! git diff e faça commit
  6. Saia e reabra com claude --permission-mode plan para confirmar que começa em plan
Ver gabarito
  • Passo 1: em versões recentes deve aparecer o auto mode; em versões ou planos onde ele não está disponível, Manual.
  • Passo 3: em plan, ele lê o tarefas.py, propõe onde criar a função editar e o novo subcomando no argparse, e pede aprovação do plano antes de qualquer edição.
  • Passo 5: o diff deve mostrar só a função nova e o registro do subcomando. Se aparecer algo a mais, peça para desfazer.
  • Passo 6: a barra de status já mostra plan ao abrir.

8Erros comuns

Ficar em Manual e aprovar tudo sem ler

Se você aprova no automático, a proteção virou teatro. Use regras (aula 4.3) para liberar o que é seguro e leia o resto.

acceptEdits sem Git

Edições sem pergunta só são tranquilas se você consegue desfazer. Commit antes.

"Plan mode não editou nada!"

É o objetivo. Ele só edita depois que você aprova o plano.

bypass "só para testar"

Fora de um ambiente isolado, não existe "só para testar" com acesso total à sua máquina.
