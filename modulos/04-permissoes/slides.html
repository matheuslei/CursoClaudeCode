Permissões e segurança

Use ← → para navegar · F para tela cheia · Ctrl+P para salvar em PDF

Os 6 modos

  • plan: investiga e planeja; não edita sem aprovação
  • default (Manual): pergunta tudo que muda algo
  • acceptEdits: edições e comandos de arquivo livres na pasta
  • auto: um classificador revisa cada ação
  • dontAsk: nega o que perguntaria (CI)
  • bypassPermissions: só em ambiente isolado

Trocar de modo

Shift+Tab # na sessão (Alt+M em alguns terminais Windows) claude --permission-mode plan # ao abrir "permissions": { "defaultMode": "default" } # como padrão

Auto mode

  • Bloqueia: curl | bash, force push, git reset --hard, deploy em produção, envio de dados sensíveis
  • Pausa após 3 bloqueios seguidos ou 20 no total
  • "Não faça X" na conversa não é regra
  • Reduz perguntas, não garante segurança

A ordem das regras

⛔ deny → ❓ ask → ✅ allow → 🎛 modo

Allow nunca abre exceção em deny. Deny vale em todos os modos.

Regras do TaskFlow

{ "permissions": { "allow": ["Bash(python -m unittest *)"], "ask": ["Bash(git push *)"], "deny": ["Read(./.env)", "Read(./.env.*)"] } }

Sandbox

  • Isola escrita (só a pasta) e rede (só domínios liberados)
  • Leitura continua ampla por padrão
  • Fora dele: Read/Edit/WebFetch, hooks, MCP, comandos com !
  • Windows nativo: não suportado; use WSL2

Segredos e dados pessoais

  • O que não deve sair não entra no contexto
  • .env + .gitignore + .env.example + deny
  • Vazou? Revogue e avise a área responsável
  • Dados reais e LGPD: consulte segurança e privacidade antes
