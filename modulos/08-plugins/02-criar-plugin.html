Criar o plugin do TaskFlow

Objetivo: juntar a skill, o hook, o servidor MCP e o subagente do TaskFlow num plugin, validar, testar numa sessão sem instalar e entender os nomes com prefixo.

▶ Vídeo da aula ~1 min

Comece por aqui: um resumo animado e narrado. Clique no vídeo ou aperte Espaço para pausar.

1Por que importa

Até aqui, as peças do TaskFlow moram em .claude/ do projeto e no settings.json. Elas só valem naquele projeto. Como plugin, você carrega tudo em qualquer projeto com uma opção na linha de comando, e depois instala por nome (aula 4).

O que mudaDuas coisas: onde os arquivos ficam (na pasta do plugin) e como eles se chamam (com o prefixo taskflow:).

2Conceito: de peças soltas a plugin

3Estrutura e regras

marketplace-taskflow/plugins/taskflow/.claude-plugin/ plugin.json ← o manifesto (só ele fica aqui dentro!) skills/ revisar-taskflow/SKILL.md nova-funcionalidade/SKILL.md padroes-taskflow/SKILL.md agents/ revisor-taskflow.md hooks/ hooks.json ← o mesmo formato do "hooks" do settings.json scripts/ checar.py servidor/ servidor_mcp.py .mcp.json ← servidores MCP do plugin README.md
O erro mais comumSó o plugin.json vai dentro de .claude-plugin/. Pastas como skills/ colocadas ali dentro não carregam. E um CLAUDE.md na raiz do plugin também não carrega: instruções vão como skill.

O manifesto

.claude-plugin/plugin.json{ "name": "taskflow", "description": "Skills, revisor, hook de sintaxe e servidor MCP do projeto de treino TaskFlow", "version": "1.0.0", "author": { "name": "Aluno do curso" } }

Só name é obrigatório (sem espaços). Ele vira o prefixo de tudo.

Caminhos: use as variáveis

Você não sabe onde o plugin será instalado. Por isso, hook e servidor apontam para os próprios arquivos com ${CLAUDE_PLUGIN_ROOT} e para o projeto com ${CLAUDE_PROJECT_DIR}.

hooks/hooks.json{ "hooks": { "PostToolUse": [ { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "python \"${CLAUDE_PLUGIN_ROOT}/scripts/checar.py\"" } ] } ] } }
.mcp.json{ "mcpServers": { "tarefas": { "command": "python", "args": ["${CLAUDE_PLUGIN_ROOT}/servidor/servidor_mcp.py"], "env": { "TASKFLOW_DIR": "${CLAUDE_PROJECT_DIR}" } } } }
Por que mexer no checar.py e no servidor?No Módulo 5, o checar.py achava o projeto pela própria posição (.claude/hooks/). No plugin ele mora em outra pasta, então passa a ler a variável CLAUDE_PROJECT_DIR, que todo hook recebe. O servidor MCP faz o mesmo com TASKFLOW_DIR para achar o tarefas.py.

Nomes com prefixo

PeçaSoltaNo plugin
Skill/revisar-taskflow/taskflow:revisar-taskflow

Servidor MCPtaskflowplugin:taskflow:tarefas no /mcp
HookSem prefixo. Se a cópia solta continuar no settings.json, ele roda duas vezes.

O ciclo de desenvolvimento

PowerShellclaude plugin validate .\marketplace-taskflow\plugins\taskflow # confere manifesto e frontmatter claude --plugin-dir .\marketplace-taskflow\plugins\taskflow # carrega só nesta sessão claude --plugin-dir .\marketplace-taskflow\plugins\taskflow plugin details taskflow # inventário e custo

Dentro da sessão: /reload-plugins aplica o que você editou; /plugin → aba Errors mostra o que falhou; /mcp mostra se o servidor conectou.

7Exercício real: o plugin taskflow

Na pasta de treino (README da etapa 08, passos 1 e 2), com o ambiente virtual ativado.

  1. Crie as pastas: New-Item -ItemType Directory -Force marketplace-taskflow\plugins\taskflow\.claude-plugin.
  2. Escreva o plugin.json do bloco 3.
  3. Copie as peças: .claude\skills e .claude\agents para dentro do plugin; o checar.py para scripts\; o servidor_mcp.py para servidor\.
  4. Crie hooks\hooks.json e .mcp.json como no bloco 3, e ajuste o checar.py e o servidor para lerem a pasta do projeto pelas variáveis. (Peça ao Claude: "ajuste estes dois scripts para achar o projeto por CLAUDE_PROJECT_DIR e TASKFLOW_DIR".)
  5. Rode claude plugin validate .\marketplace-taskflow\plugins\taskflow até aparecer ✔ Validation passed.
  6. Para evitar o hook duplicado, apague o bloco "hooks" de .claude\settings.json e as pastas soltas .claude\skills, .claude\agents e .claude\hooks da pasta de treino.
  7. Abra claude --plugin-dir .\marketplace-taskflow\plugins\taskflow. Digite /taskflow: e veja as skills; peça "use o subagente taskflow:revisor-taskflow para revisar o tarefas.py". Opcional, se você instalou o pacote mcp (passo 2 do README; exige Python 3.11 ou mais novo): rode /mcp e veja o servidor plugin:taskflow:tarefas. Sem o pacote, ele aparece com erro de conexão, e tudo bem: a aula se conclui com skills, subagente e hook.
  8. Edite a description de uma skill, rode /reload-plugins e confira que a mudança valeu.

8Erros comuns

Peças dentro de .claude-plugin/

Só o plugin.json vai ali. O resto fica na raiz do plugin.

Caminho fixo

Use ${CLAUDE_PLUGIN_ROOT}; o plugin instalado fica em outra pasta.

Hook duplicado

Hooks não têm prefixo: remova a cópia do settings.json.

--plugin-dir na pasta errada

Aponte para a pasta do plugin (a que tem .claude-plugin/plugin.json), não para a do marketplace.
