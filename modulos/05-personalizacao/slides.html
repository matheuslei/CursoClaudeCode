Orientar × garantir

  • CLAUDE.md, skills, output styles: instruções que o Claude segue
  • settings.json (permissões, hooks): aplicado pela ferramenta, sempre
  • Precisa acontecer sem exceção? → hook

Precedência de settings

🏢 Gerenciado › ⌨ --settings › 🔒 local › 👥 projeto › 👤 usuário

  • Listas (permissions.allow) se somam
  • /status → Setting sources · /config chave=valor
  • JSON estrito: sem comentários, sem vírgula sobrando

Onde fica cada coisa

  • .claude/settings.json: time · .claude/settings.local.json: só você
  • .claude/skills/<nome>/SKILL.md: skills
  • .claude/output-styles/*.md: estilos
  • ~/.claude/…: as mesmas coisas, para todos os seus projetos

Skill em 30 segundos

--- description: Revisa o diff do TaskFlow. Use quando pedirem revisão. argument-hint: [foco] --- !`git diff HEAD` Revise o diff acima. Foco: $ARGUMENTS
  • Chame com /revisar-taskflow erros · /skills · /skill-doctor

Quem chama a skill?

  • Padrão: você e o Claude (pela description)
  • disable-model-invocation: true: só você
  • user-invocable: false: só o Claude
  • .claude/commands/: formato antigo; prefira skills

Output styles e status line

  • Concise direto · Explanatory com ★ Insight · Learning com TODO(human) · Proactive assume e segue
  • /output-style learning · no settings: "Learning" (maiúscula!)
  • /statusline mostre modelo e contexto; no Windows, caminhos com /

Hooks

"hooks": { "PostToolUse": [ { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "python .claude/hooks/checar.py" } ] } ] }
  • PreToolUse pode bloquear · PostToolUse verifica · exit 2 bloqueia, exit 1 não!

Segurança

  • Hooks e skills rodam comandos com as suas permissões
  • Leia hooks e skills de terceiros antes de usar (/hooks mostra a origem)
  • Nunca coloque segredos em settings commitados
